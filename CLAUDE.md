**Reliability comes first.** This is a sensitive field: wrong quantities go into orders, estimates and contracts. Every answer must end in one of three states: ✅ Verified (no need to double-check, backed by measured error rates on held-out drawings), 🟡 Check this (evidence highlighted), or ⛔ Can't answer reliably (with the reason). A wrong Verified answer is the worst possible outcome; abstaining is always allowed. Numbers are computed from enumerated objects and geometry, never generated by a language model. See `03-strategy/RELIABILITY.md`.

## The mission

Build a program that **answers natural-language questions about construction drawings and building models, accurately and verifiably**, and show where in the drawing each answer came from so a human can check it in seconds. Stoa wants approaches that **next year's frontier models won't make obsolete**: hybrids of frontier models, computer vision, 3D, geometry and small fine-tuned models.

Judging (25% each): **accuracy**, **how well the solution visualizes its reasoning so a human can verify the answer**, **creativity**, **low inference cost**.
Prizes: 1st €1,000 + a work trial at Stoa · 2nd €750 · 3rd €250.

The team's own goal on top: a demo with a **big visual "wow"** that is also **measurably correct**. Every visual must be evidence, not decoration.

## What the data tells us (see `02-dataset/DATASET.md`)

- ~14,000 drawings (PDF, DWG, DXF, IFC, SVG, PNG, JPEG) in ~30 languages; ~127,000 questions in `questions.jsonl` with `{path, question, answer, unit, type}`. Every question names its file.
- Scoring rule from the dataset README: **counts exact; areas, lengths, volumes within 2%; text free-form.**
- Question mix (full set): count 88%, area 11%, text 0.7%, volume/length tiny. By source: cubicasa5k 67% (Finnish floor-plan PNGs, symbol counts), swiss_dwellings 30% (PDF + DXF + PNG of the same floor: counts and areas), ifc_models 2.4% (IFC + PDF/PNG/SVG plans rendered from it), ifc_bench 0.6% (IFC text questions from the IFC-Bench v2 benchmark), opening_design 64 questions (real US drawing sets: door schedules).
- **Files with the same name and a different extension are the same drawing.** Use the most structured format available: IFC > DXF/DWG > vector PDF/SVG > raster.

## The approach in one sentence

A **router** that sends each question to the cheapest method that can answer it exactly (IFC queries, DXF/PDF vector geometry, a small symbol detector), falls back to a frontier vision model only when needed, and returns every answer with its **evidence**: the boxes, polygons or model elements it counted or measured, drawn on the drawing and in 3D.

## Ground rules

1. **Measure everything.** Build the evaluation harness first: run on a fixed, stratified sample of questions per source and type, score with the dataset's rule (exact counts, 2% tolerance), log accuracy, latency and **€ per question** to `results/`. Every claim in the pitch comes from this log.
2. **Hold out data honestly.** Split by drawing (not by question) into dev and test; never tune on test. Cubicasa5k and Swiss Dwellings are public datasets with public annotations. Do **not** look answers up from public annotations; that is leakage and would not work on Stoa's own drawings. Ask Stoa at their booth how accuracy will be judged (held-out questions? new drawings? live questions?) and whether training a detector on public annotations is acceptable.
3. **Cheap first.** Deterministic geometry costs ~€0. A small detector costs fractions of a cent. A frontier VLM call is the last resort, and its cost is shown in the UI.
4. **Abstain rather than guess** when methods disagree or confidence is low; show "needs review" with the evidence. A wrong confident answer hurts both accuracy and trust.
5. **Respect licences.** Each source folder has a `LICENSE.md`; keep the credit when showing a drawing. CubiCasa5k is NonCommercial; fine for the challenge.
6. Junction rule: all code written at the event (open-source libraries fine); the repo is MIT-licensed on submission.

## Setup

1. Download the preview first (0.5 GB zip, ~730 MB unpacked): see `02-dataset/download.sh`. Move to the full set (~10 GB zip, ~12 GB unpacked) only when the pipeline works.
2. Python 3.11+ recommended. Core libraries: `ifcopenshell`, `ezdxf`, `pymupdf` (fitz), `shapely`, `numpy`, `opencv-python`, `ultralytics` (YOLO) or a similar detector, plus one VLM SDK (see `03-strategy/TECH-PARTNERS.md`). DWG needs conversion to DXF (ODA File Converter or LibreDWG).
3. Front end: a web app (React/Vite or Next.js) with a 2D canvas overlay (SVG/Konva/Pixi) and Three.js / That Open Components for 3D and IFC.

## Build order

1. Data loader + eval harness + baseline (a frontier VLM answering every question from the image alone). Record its accuracy and cost: this is the number we beat.
2. **IFC path** (ifc_models, ifc_bench): IfcOpenShell queries for counts, areas, volumes, lengths; an agent that writes and runs IfcOpenShell code for text questions (the approach that scored best on IFC-Bench v2, see research).
3. **DXF/vector path** (swiss_dwellings): room polygons + labels → exact areas and counts; door/window entities → counts.
4. **Raster path** (cubicasa5k): symbol detector for doors, windows, toilets, sinks, showers/bathtubs, saunas; room label OCR for bedrooms etc. Every detection is a box with a number.
5. **Router + verifier + calibration**: pick the path by file type and question type; cross-check with independent methods (including the areas printed on the drawing); compute the Verified / Check / Can't-answer state; set the Verified threshold per question family on a calibration split so the error rate among Verified answers stays under the target (RELIABILITY.md §4).
6. **Verification UI** (the 25% visual criterion and the wow): see `03-strategy/WOW-DEMO.md`.
7. Cost dashboard + final numbers for the pitch.
